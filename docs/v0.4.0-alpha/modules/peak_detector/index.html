峰值检测器 ​

适用：v0.4.0-alpha · GNU Radio 3.10.12.0
模块类型：peak_detector · 模块定义版本：1

是什么 ​

从相关帧中寻找唯一的最大绝对值，输出它所在的有符号 lag、保留符号的相关值，以及用真实原始采样率换算出的秒数。它为“样本数怎样变成传播时间”提供中间步骤，不给出目标识别或检测置信度。

例如 +6 和 −6 的绝对值都是 6；判断峰位置时比较大小 6，输出相关值时仍分别保留 +6 或 −6。两个位置同时达到最大绝对值则没有唯一峰，不能任意挑一个。

典型接线 ​

相关器.correlation → 峰值检测器.correlation，再把 delay_s 直接交给测距器。lag_samples、peak_value 和 delay_s 可分别捕获，核对“几步”“乘加值”“几秒”。

下表为内置默认参数下的端口。带路数、元素类型或 vlen 的模块会随参数改变流端口。

方向端口数据类型单位 / 形状
输入correlation（完整相关帧）numeric_f64原始相关值；vlen=127
输出lag_samples（有符号滞后）numeric_f64样本；vlen=1
输出peak_value（有符号峰值）numeric_f64原始相关值；vlen=1
输出delay_s（延迟）numeric_f64s；vlen=1

首版只接受相关器直接输出。N、分量形状和 lag 轴必须一致，轴上保存原始 Fs。普通向量即使长度相同也不能接入；相关器与峰值检测器之间不能插入普通增益或加法模块，因为这些模块暂不传播 lag 轴。不要通过手填单位或变量名绕过来源约束。

参数怎么用 ​

frame_length 与上游相关器的 N 一致。min_abs_peak 比较的是相关结果的绝对值，且必须严格高于阈值；等于阈值也不通过。原始相关会随输入幅度和窗口内容变化，不能把阈值解释成百分比。

内置默认值如下；本机设置可为新实例指定其他默认值，打开已有工程保留工程参数。

参数内置默认值取值与约束修改时机
非重叠窗口点数 N
frame_length		64范围 8 至 512重新准备
最小绝对峰值（须严格超过）
min_abs_peak		0范围 0 至 3.4028234663852886e+38重新准备

默认值和参数范围见上表。选出峰后按 delay_s=lag_samples/原始 Fs 换算；分母是相关器输入采样率，不是相关帧率。原始 Fs 尚未知时，不能补造一个速率生成秒数。

在线修改与重新准备 ​

计算参数或结构变化后，先停止，再重新准备和运行。

本模块不提供在线参数修改。帧长调整需与相关器保持一致并重新准备。重准备清除此前状态，旧峰与旧缓存不能证明新参数已经执行。

示例与观察 ​

把延迟换成传播距离 ​

下载 03-delay-to-distance.cnsproj

在 PC 上打开工程，按 F5 运行。有限运行可将参考源样本数设为 64 item；重新打开工程后需再次运行以取得数据。

把延迟换成传播距离

  • lag=2 → 0.002 s → 0.34 m，采用 340 m/s 往返传播教学模型；仅把延时改为 3 后为 0.51 m。

相关找延迟先在完整 N=8 的相关图上手工读峰：参考峰位于 +2 sample，相关值为 +6。延迟换距离才加入本模块，用原始 Fs=1000 sample/s 自动换算出 delay_s=0.002 s，再计算米值。

相关父向量在单独观察器以单路“相关值—滞后”图读取；三个标量输出可独立核对。不要把相关向量中相邻 lag 看成相邻时间点，也不要把峰值符号改成正数后再记录。

常见问题与失败边界 ​

静默窗口或两个并列绝对峰怎么办？ 最大绝对值不高于阈值、或最大值并列时，任务失败并给出位置说明，不伪造一个峰。相关器仍保留真实相关结果；含本模块的任务不能以“相关帧算出来了”冒充全链成功。

负峰会产生负距离吗？ 峰值符号与 lag 符号各有含义。rx 反号可以保持 lag=+2 而输出峰值 −6；delay_s 仍可为正。负 lag 则产生负延迟，后接测距器会按负延迟规则失败。

零 lag 是无效占位吗？ 不是。合法的唯一零 lag 可输出 0 s，进而得到 0 m；不可把失败也写成零混在一起。

失败后为什么还有数值？ 保留最后有效数据和任务失败状态，不再产生新的有效检测结果。不要把旧点当成新结果，也不能给无峰情况补一个零。

每帧都有唯一峰，能证明存在目标吗？ 不能。它只说明该窗口的算术最大值唯一。周期重复、截断及跨窗歧义仍须结合真实输入解释。
